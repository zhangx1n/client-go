# 02 - 三种客户端：跟 K8s 资源做 CRUD

> 上一篇你学会了怎么连接 API Server。这一篇教你三种跟 K8s 资源交互的方式。

---

## 你会学到什么

- Typed Clientset：类型安全的内置资源客户端
- Dynamic Client：操作任意资源（包括 CRD）的通用客户端
- Discovery Client：查询集群支持哪些 API
- 三种客户端各自适合什么场景

---

## 1. Typed Clientset — 最常用的客户端

### 一句话理解

Typed Clientset 就像一个"强类型的 K8s SDK"。对每种资源（Pod、Deployment、Service...），都有专门的方法，参数和返回值都是明确的 Go 类型。

### 怎么创建

```go
import "k8s.io/client-go/kubernetes"

clientset, err := kubernetes.NewForConfig(config)  // config 来自上一篇
```

**源码位置：** `kubernetes/clientset.go:476`

### Clientset 的结构

**源码位置：** `kubernetes/clientset.go:141-196`

Clientset 内部包含 30+ 个 API Group 的客户端：

```go
type Clientset struct {
    admissionregistrationV1       *admissionregistrationv1.AdmissionregistrationV1Client
    appsV1                        *appsv1.AppsV1Client
    batchV1                       *batchv1.BatchV1Client
    coreV1                        *corev1.CoreV1Client
    // ... 30+ API Group 客户端
}
```

通过方法访问各 Group：
```go
clientset.CoreV1()              // Pod, Service, ConfigMap, Secret, Namespace...
clientset.AppsV1()              // Deployment, StatefulSet, DaemonSet, ReplicaSet...
clientset.BatchV1()             // Job, CronJob
clientset.NetworkingV1()        // Ingress, NetworkPolicy
clientset.RbacV1()              // Role, ClusterRole, RoleBinding...
```

### 使用示例

```go
// 获取 Pod
pod, err := clientset.CoreV1().Pods("default").Get(ctx, "my-pod", metav1.GetOptions{})

// 列出 Deployment
deployList, err := clientset.AppsV1().Deployments("default").List(ctx, metav1.ListOptions{})

// 创建 Service
svc, err := clientset.CoreV1().Services("default").Create(ctx, &v1.Service{...}, metav1.CreateOptions{})

// 更新 Deployment
deploy, err := clientset.AppsV1().Deployments("default").Update(ctx, deploy, metav1.UpdateOptions{})

// 删除 Pod
err = clientset.CoreV1().Pods("default").Delete(ctx, "my-pod", metav1.DeleteOptions{})

// Watch（监听变化）
watcher, err := clientset.CoreV1().Pods("default").Watch(ctx, metav1.ListOptions{})
```

### 更新时的冲突处理 — retry.RetryOnConflict

**这是一个极其重要的模式。** 当多个客户端同时修改同一个资源时，后修改的会收到 409 Conflict 错误。正确做法是重试：

```go
import "k8s.io/client-go/util/retry"

err := retry.RetryOnConflict(retry.DefaultRetry, func() error {
    // 1. 每次重试都重新获取最新版本
    deploy, err := clientset.AppsV1().Deployments("default").Get(ctx, "nginx", metav1.GetOptions{})
    if err != nil {
        return err
    }

    // 2. 修改
    deploy.Spec.Replicas = int32Ptr(3)

    // 3. 更新
    _, err = clientset.AppsV1().Deployments("default").Update(ctx, deploy, metav1.UpdateOptions{})
    return err
})
```

**对应示例：** `examples/create-update-delete-deployment/main.go:126-141`

### 小白问答

**Q: 为什么要"每次重试都重新 Get"？**

A: K8s 资源有一个 `resourceVersion` 字段。Update 时 API Server 会检查你提交的 `resourceVersion` 是不是最新的。如果不是（说明别人已经改过了），就返回 409 Conflict。重新 Get 获取最新版本后再 Update 就能成功。

**Q: 这些类型化客户端代码是手写的吗？**

A: 不是，全部是 `code-generator` 工具自动生成的。Kubernetes 定义好 API 结构（在 `k8s.io/api` 仓库），然后用 `client-gen`、`lister-gen`、`informer-gen` 等工具自动生成客户端代码。

## 2. Dynamic Client — 万能客户端

### 一句话理解

Dynamic Client 不需要知道资源的 Go 类型定义，用 `map[string]interface{}` 来表示任何 K8s 对象。特别适合操作 CRD（自定义资源）。

### 怎么创建

```go
import "k8s.io/client-go/dynamic"

dynamicClient, err := dynamic.NewForConfig(config)
```

**源码位置：** `dynamic/simple.go:79`

### 接口定义

**源码位置：** `dynamic/interface.go:29-50`

```go
// interface.go:29
type Interface interface {
    // 通过 GVR 指定要操作的资源类型
    Resource(resource schema.GroupVersionResource) NamespaceableResourceInterface
}

// interface.go:33 — 资源操作接口（和 Typed Client 类似的 CRUD）
type ResourceInterface interface {
    Create(ctx context.Context, obj *unstructured.Unstructured, ...) (*unstructured.Unstructured, error)
    Update(ctx context.Context, obj *unstructured.Unstructured, ...) (*unstructured.Unstructured, error)
    Delete(ctx context.Context, name string, ...) error
    Get(ctx context.Context, name string, ...) (*unstructured.Unstructured, error)
    List(ctx context.Context, opts metav1.ListOptions) (*unstructured.UnstructuredList, error)
    Watch(ctx context.Context, opts metav1.ListOptions) (watch.Interface, error)
    Patch(ctx context.Context, name string, ...) (*unstructured.Unstructured, error)
}
```

### 核心概念：GVR（GroupVersionResource）

使用 Dynamic Client 需要指定资源的 GVR：

```go
// Deployment 的 GVR
gvr := schema.GroupVersionResource{
    Group:    "apps",      // API 组（core 资源为空字符串 ""）
    Version:  "v1",        // API 版本
    Resource: "deployments", // 资源名称（复数形式）
}

// Pod 的 GVR
podGVR := schema.GroupVersionResource{Group: "", Version: "v1", Resource: "pods"}

// 自定义资源的 GVR
crdGVR := schema.GroupVersionResource{
    Group: "example.com", Version: "v1", Resource: "myresources",
}
```

### 使用示例

```go
gvr := schema.GroupVersionResource{Group: "apps", Version: "v1", Resource: "deployments"}

// 列出 Deployment
list, err := dynamicClient.Resource(gvr).Namespace("default").List(ctx, metav1.ListOptions{})

// 遍历结果
for _, item := range list.Items {
    name := item.GetName()
    replicas, found, _ := unstructured.NestedInt64(item.Object, "spec", "replicas")
    fmt.Printf("Deployment: %s, Replicas: %d\n", name, replicas)
}
```

### 核心概念：Unstructured

`unstructured.Unstructured` 本质就是 `map[string]interface{}`：

```go
// 创建一个非结构化对象
deployment := &unstructured.Unstructured{
    Object: map[string]interface{}{
        "apiVersion": "apps/v1",
        "kind":       "Deployment",
        "metadata": map[string]interface{}{
            "name": "my-deploy",
        },
        "spec": map[string]interface{}{
            "replicas": 3,
            // ...
        },
    },
}

// 读取嵌套字段
replicas, found, err := unstructured.NestedInt64(obj.Object, "spec", "replicas")

// 设置嵌套字段
unstructured.SetNestedField(obj.Object, int64(5), "spec", "replicas")
```

**对应示例：** `examples/dynamic-create-update-delete-deployment/main.go`
- 第 66-105 行：构造 Unstructured 对象
- 第 131-160 行：读取和修改嵌套字段

**源码位置：** `dynamic/simple.go`

- `DynamicClient` 结构体：第 34-36 行

## 3. Discovery Client — API 发现

### 一句话理解

Discovery Client 用来问 API Server："你支持哪些 API？有哪些资源类型？"。这在编写通用工具（如 kubectl）时很有用。

### 怎么创建

```go
import "k8s.io/client-go/discovery"

discoveryClient, err := discovery.NewDiscoveryClientForConfig(config)
```

**源码位置：** `discovery/discovery_client.go:748`

### 接口定义

**源码位置：** `discovery/discovery_client.go:79-90`

```go
type DiscoveryInterface interface {
    RESTClient() restclient.Interface
    ServerGroupsInterface       // 查询 API 组
    ServerResourcesInterface    // 查询资源类型
    ServerVersionInterface      // 查询服务器版本
    // ...
}
```

### 使用示例

```go
// 获取所有 API 组
groups, err := discoveryClient.ServerGroups()
for _, g := range groups.Groups {
    fmt.Println(g.Name)  // "", "apps", "batch", "networking.k8s.io"...
}

// 获取某个组下的资源
resources, err := discoveryClient.ServerResourcesForGroupVersion("apps/v1")
for _, r := range resources.APIResources {
    fmt.Printf("  %s (%s)\n", r.Name, r.Kind)
    // deployments (Deployment), statefulsets (StatefulSet)...
}

// 获取服务器版本
version, err := discoveryClient.ServerVersion()
fmt.Printf("Server version: %s\n", version.GitVersion)
```

### 小白问答

**Q: 什么时候需要用 Discovery Client？**

A: 大多数时候你不需要直接用它。它主要在这些场景有用：
1. 写通用工具，需要知道集群支持哪些资源
2. 动态客户端配合使用，先 Discovery 找到 GVR，再用 Dynamic Client 操作
3. 判断集群是否支持某个 API（比如检查是否支持 `networking.k8s.io/v1`）

## 4. 三种客户端对比

| 特性 | Typed Clientset | Dynamic Client | Discovery Client |
|------|----------------|----------------|-----------------|
| **类型安全** | 是（编译期检查） | 否（运行时 map） | N/A |
| **支持 CRD** | 需要 code-gen | 原生支持 | N/A |
| **性能** | 最优（直接反序列化） | 稍慢（JSON → map） | N/A |
| **易用性** | 最好（IDE 补全） | 较差（需手动操作 map） | 简单 |
| **主要用途** | 操作内置资源 | 操作 CRD / 通用工具 | 查询 API 能力 |
| **创建方式** | `kubernetes.NewForConfig()` | `dynamic.NewForConfig()` | `discovery.NewDiscoveryClientForConfig()` |

### 选择建议

```
你要操作的是 K8s 内置资源（Pod, Deployment 等）？
  └── 是 → 用 Typed Clientset
  └── 否 → 你要操作 CRD / 自定义资源？
              └── 是 → 用 Dynamic Client
              └── 否 → 你要查询集群支持什么 API？
                          └── 是 → 用 Discovery Client
```

## 5. 它们的关系

三种客户端底层都用同一个 REST 客户端：

```
                     rest.Config
                         │
                         ▼
                    RESTClient（HTTP 引擎）
                    /        |        \
                   /         |         \
                  ▼          ▼          ▼
           Typed         Dynamic     Discovery
           Clientset     Client      Client
           │             │           │
           │             │           │
           ▼             ▼           ▼
       强类型 CRUD    万能 CRUD    API 查询
       (Pod,Deploy)  (任意资源)   (Groups,Resources)
```
